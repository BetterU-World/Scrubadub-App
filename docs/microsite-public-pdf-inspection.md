# Microsite public PDF inspection

Company Documents remains the canonical file owner. The My Site picker uses the same upload intent, candidate registration, and finalization workflow as the Documents hub. Saving, hiding, or removing a microsite listing does not create a copy or modify private client assignments. Existing documents have no public designation. An owner designates a PDF by requesting its check, acknowledges that anyone can download the exact version, and saves a visible entry on a published site.

## Settings and responsibilities

Verify the Vercel project's Node runtime supports the pinned Sandbox SDK `5.0.0` (Node 22.19 or newer). Both SCRUB Vercel projects use Node 24.x. Verify Secure Backend Access with OIDC in the target project's settings. The SDK uses the project-scoped Vercel OIDC identity outside the guest. The inspection guest receives neither OIDC nor application credentials.

Provision a **dependency-only** snapshot in each target Vercel project. From an authenticated shell with that project's short-lived OIDC context, run `node scripts/provision-microsite-pdf-snapshot.mjs`. The script pins the official Python sandbox base digest, downloads the official QPDF 12.4.2 Linux amd64 ZIP, verifies SHA-256, verifies the executable version, closes egress, and snapshots the dependency-only VM. The artifact is pinned by snapshot ID. Keep customer documents out of this process. Review the dependency notices in the upstream distribution (QPDF Apache-2.0 plus third-party notices) and release advisories during updates. A snapshot expires after 30 days unless replaced. Rotate an expiring snapshot before it expires, retain the old one briefly for rollback, then delete it.

The Convex action sends only an inspection ID and nonce to Vercel. Vercel requests the bytes from the private Convex endpoint, avoiding Vercel's default incoming payload limit. Convex checks the one-time claim, immutable storage ID, company, current designation, status, and measured size before supplying the file. Only the trusted function handles the credentials. It verifies deny-all networking and nonpersistence before writing bytes through the Sandbox control plane. It launches the fixed parser with one vCPU, no ports or drives, 35 seconds of platform lifetime, and a 12-second command deadline. Shutdown is attempted in a finally block. The sandbox never creates a snapshot. A provider timeout can take additional time to show as stopped.

The job stores version identifiers and a small outcome, with time and attempt count. A first check is scheduled independently of the owner page. Concurrent checks reuse the same generation. Rejections are reused for the same storage ID, policy, and inspector. The owner can explicitly retry one transient failure. Bump the policy or inspector version if protection changes or an advisory requires reinspection. Existing passing results under the former policy cease to authorize downloads immediately. If responding to a consequential issue, suspend new inspections, suspend affected public transfer, update the dependency and policy versions, then require owners to check and approve the affected file versions again.

## PDF profile and residual risk

- Eligibility requires an active canonical PDF of at most 10,485,760 bytes. No private filename or document ID is in the public URL, card, or attachment filename.
- QPDF runs with cross-reference recovery disabled. Warnings and errors fail closed. A second run exports the object graph, including supported compressed objects. The policy rejects encrypted files, embedded or external files, action and annotation trees, forms, JavaScript, launch, rich media, unsupported stream filters, incremental or hybrid trailers, and ambiguous or unsupported structures. Only Flate and JPEG stream filters are allowed in this initial profile. PDFs with links, forms, or unsupported exports may need a new static export.
- Each parser process has a 256 MiB address-space limit, 3 CPU seconds, 4 wall seconds, a 24 MiB file-output limit, 32 descriptors, and core dumps disabled. The wrapper has a 384 MiB address-space limit. The 24 MiB serialized graph cap also bounds fully decoded stream bytes emitted by QPDF. JPEG image data remains a compressed payload under the generalized decoder. Parser object and nesting limits, 12,000 top-level graph records, and 120,000 traversed nodes provide additional bounds.
- Guest diagnostics can contain PDF material and remain in short-lived guest scratch files. The guest emits one status word. The application never stores a PDF copy or parser output. Structural inspection and attachment delivery leave residual malware, reader vulnerabilities, and retained download risk.

## Limits, billing, and monitoring

Ten entries per site, 100 characters for public titles, 320 for descriptions, and 80 for section headings. Inspection limits are 10 launches per company per hour, 250 launches per UTC day across the deployment, 3 active leases across the deployment, and 2 attempts for one exact file and policy. These caps apply before scheduling billed work. Expired leases fail closed. Set the internal `micrositeResources:setInspectionSuspension` switch to suspend new inspections and unclaimed transfers. An owner changing display text or visibility never starts an inspection.

Downloads are on demand and return attachment, no-store, nosniff, and noindex headers. Every request verifies the current site and section visibility, entry, owner-approved exact file version, passed policy result, file existence, and suspension. The Phase 3A operator suspension covers both documents and images. PDFs have a separate 128 MiB hourly company allowance, so document traffic cannot consume the existing 512 MiB image allowance. Requests over the PDF limit receive 429. A replacement, archive, removal, or hide revokes the old URL on subsequent requests. Archived files require explicit approval again after restoration.

Plan for one Vercel Function invocation, one authorization-constrained Convex file read, plus Convex job state and worker calls per launch. A typical 1 MiB file adds about $0.13 in Convex data egress per 1,000 inspections at $0.12/GB after included usage. Ten MiB per inspection adds about $1.26 per 1,000. The earlier sandbox case measured 2.2 active CPU seconds and 6.9 seconds elapsed across the synthetic matrix. A hypothetical 1,000 one-vCPU sessions at that CPU usage and a one-minute billed 2 GB allocation would cost about $0.79 in sandbox compute at published iad1 rates. The measured 181 MB dependency snapshot would add about $0.015 per month at $0.08/GB-month. Function compute, platform transfer classifications, retries, and usage credits affect actual spend. The billing API returned no finalized charges for the QA runs.

Before release, configure and confirm Vercel spend alerts, Sandbox usage dashboards, and Convex usage thresholds with the founder. Monitor sandbox creations, CPU, billed memory, snapshot age, Convex file egress, unavailable-result rates, and circuit-breaker trips. Direct Convex delivery is outside Vercel WAF.

## Founder verification

In a nonproduction configuration, choose an existing PDF and upload a new one through My Site. Confirm one canonical file and record per upload. Begin inspection and leave the editor, then reopen and approve the passed version. Check both templates, EN and ES labels, private download, card preview, and public download on an iPhone and Android phone. Replace and archive the canonical file, hide the listing, disable the section, and unpublish the site while checking that captured URLs return 404. Confirm operator suspension, tenant and global limits, and that customer portal assignments still work. Keep Phase 3B disabled in production until the required Phase 3A production smoke checks and founder review are complete.

## Issues found and fixed

1. **Incomplete snapshot approval bypass:** `pause` previously accepted a preparing run; `reviewPausedRun` could then mark it ready without finishing the entrant scan. Pause now accepts only approved/already-paused delivery runs. Regression proves an incomplete run remains preparing and cannot enter approval review.
2. **Recovery blocked by configuration drift:** provider acceptance reconciliation previously required the old run's configuration to match today's settings. Reconciliation now validates the historical reservation independently; a key/config/content change still blocks subsequent approval and sending until a new reviewed run exists. Invalid/non-finite accepted timestamps are rejected.
3. **Authentication-pepper coupling:** campaign identity previously changed with the existing session pepper, potentially invalidating suppression lookups or delivery keys after rotation. Version 4 uses a stable canonical-email digest, with HMAC signing separately authorizing opt-out. Session authentication still uses the existing pepper. As this is a pre-release change, rebuild earlier preview-only snapshots and re-import the authoritative source suppressions before operational tests; do not reuse earlier test data as a production audit or discard real delivery history. If any environment has actually sent an earlier campaign revision, stop for private migration/reconciliation before adopting new identities.
4. **Malformed audit data:** non-finite qualification/eligibility/consent timestamps and future eligibility/consent records now fail closed. Strict boolean consent, required consent version, normalization, duplicate holds, winner exclusion and current suppression checks remain enforced.
5. **Untrusted webhook resource use:** the public route previously read the whole body before enforcing its limit. It now caps bytes while streaming. Actual Resend/Svix verification is tested with signed, tampered, stale and unsigned payloads; valid replay produces one persistent suppression.

All public administration functions verify an existing active staff session and active platform-admin entitlement before reading or writing. Tests enumerate preview, status, ledger, preparation, test preparation, approval, pause/review, suppression, reconciliation and delivery controls. Anonymous exceptions are only authenticated signed-link opt-out and signature-verified provider events; neither sends mail. Helpers/internal operations are not public send endpoints.

Existing general email transport/identity functions are unchanged. Campaign identity overrides are scoped to the new action. Existing email-identity and giveaway regressions pass. No campaign calls are registered in crons or schedulers, and the admin component's mutation/action calls occur only in explicit event handlers.
